# pafi-setup

Generate a ready-to-launch PAFI job from three user-supplied ingredients:

1. **A calculator-loading Python file** — defines / returns an ASE
   `Calculator`. The agent imports from this; it does not rewrite it.
2. **A list of ASE systems** — the NEB pathway, as a single trajectory file,
   a directory of numbered images, or a Python loader.
3. **(Optional) a submission-script template** — a SLURM / PBS / LSF / shell
   template the agent fills in (account, partition, walltime, `mpirun` line,
   module loads, etc.).

The agent produces:

- `run_pafi.py` — the PAFI driver, written into the user's folder.
- `submit_pafi.sh` (or the template's extension) — a filled-in submission
  script, if a template was supplied.
- A printed launch command (`sbatch submit_pafi.sh`, `mpirun …`, or
  `python run_pafi.py`).

The repo root (`README.md`, `mpi-ase-test.py`, `eam-test.ipynb`) is the
source of truth for the PAFI API — re-read it if anything below looks stale.

## When to use

Trigger when the user asks to set up, scaffold, submit, or generate a PAFI
run and provides (or points at) a folder. Typical phrasings:

- "set up PAFI for the system in `./my-system/`"
- "here's a calculator file and a NEB traj, wire them into PAFI"
- "generate a SLURM script to run PAFI on this cluster"

If the user has not named a folder, ask which folder to inspect before doing
anything else.

## Step 1 — inventory the user folder

List the folder and classify each file into the three slots. Accept:

**Calculator file** — any Python file that (a) exposes a factory like
`make_calculator(comm=None)` or `get_calculator(...)`, or (b) constructs a
module-level `calc = ...`. Look for `MACECalculator`, `LAMMPSlib`, `EMT`,
`SevenNetCalculator`, custom `Calculator` subclasses. If only a potential
file (`*.eam.fs`, `*.model`, `*.pt`) plus a README is present, ask the user
to point at or create a loader — do **not** invent the calculator
construction yourself (wrong potential = meaningless free energies).

**NEB pathway** — any of:
- ASE-readable trajectory: `*.traj`, `*.xyz`, `*.extxyz`, `POSCAR*`, `*.cif`.
  Must load as a list of `Atoms` via `ase.io.read(path, index=":")`.
- A directory of numbered images (`image_00.xyz`, …) — read with a glob.
- A Python script that builds `images` (e.g. runs an NEB). Import from it
  rather than re-executing NEB logic inside `run_pafi.py`.

**Submission template** (optional) — `*.sh`, `*.sbatch`, `*.slurm`, `*.pbs`,
or any file whose header looks like `#SBATCH` / `#PBS` / `#BSUB`. Treat it
as a template: keep the user's directives (account, partition, QoS, modules,
`conda activate`, etc.) and only fill in the placeholders / the `mpirun`
line. If the template contains obvious placeholders (`{NTASKS}`, `<JOBNAME>`,
`TODO`), resolve them or ask.

If any slot is ambiguous or missing (and is required), stop and ask. Never
silently substitute defaults for the calculator or NEB path.

## Step 2 — confirm the plan

Before writing files, state back:

- which file is the calculator and which symbol you will import
  (`from user_calc import make_calculator`),
- which file(s) provide the NEB images and how they will be loaded,
- **serial `PAFI` vs. MPI `PAFIMPI`.** Use MPI whenever a submission
  template is involved or the calculator is MPI-aware. Otherwise ask.
- the `worker_comm` layout: 1 rank per worker (`COMM_SELF`, default, works
  for LAMMPSlib) vs. multi-rank workers (needed for MPI-parallel
  calculators). This choice drives the `mpirun -n` count.
- the `(r, T, nsteps, thermsteps)` grid. If unspecified, propose a smoke
  test (e.g. `r = np.linspace(0, 1, 11)`, one `T`, `nsteps=100`,
  `thermsteps=100`) and label it as such.
- which submission template you will fill in, and what values you plan to
  set (ntasks, walltime, job name, output path).

Proceed once the user confirms or says "use sensible defaults".

## Step 3 — write `run_pafi.py` into the user's folder

Shape (adapt to serial vs. MPI, and to the user's loader names):

```python
# run_pafi.py — generated by the pafi-setup skill
import os, numpy as np
from ase.io import read
from mpi4py import MPI                      # omit for serial
from pafiase import PAFIMPI                 # or PAFI for serial

from user_calculator import make_calculator # user's file / factory

# --- NEB images -------------------------------------------------------------
images = read("<path-to-traj>", index=":")

# --- Calculator (comm must match worker_comm) -------------------------------
worker_comm = MPI.COMM_SELF
inter_comm  = MPI.COMM_WORLD
calc = make_calculator(comm=worker_comm)

pafi = PAFIMPI(images, calc, worker_comm=worker_comm, inter_comm=inter_comm)

json_file = "pafi_results.json"
if os.path.exists(json_file):
    pafi.read_json(json_file)

rank = MPI.COMM_WORLD.Get_rank()
for T in [300.0]:
    for r in np.linspace(0.0, 1.0, 11):
        pafi.run(r, T=T, nsteps=500, thermsteps=500, verbose=(rank == 0))
        if rank == 0:
            pafi.write_json(json_file)
```

Rules:

- Always wire `read_json`/`write_json` — PAFI runs are long, restarts matter.
- Rank 0 only for prints and JSON writes (see `mpi-ase-test.py`).
- Pass the **same** `worker_comm` to the calculator that goes to `PAFIMPI`.
  Mismatched comms is the #1 MPI-PAFI bug and is called out in the README.
- Import the user's loader — do not inline their calculator construction.
- No argparse / CLI unless requested.

## Step 4 — fill in the submission template

Work from the user's template, not a hand-written one. Typical edits:

- `--job-name`, `--output`, `--error` → use the folder name.
- `--ntasks` / `-n` → the number of PAFI workers (times ranks-per-worker if
  using multi-rank workers).
- `--time`, `--partition`, `--account`, `--qos` → leave user's values alone
  unless they asked you to change them; resolve only obvious placeholders.
- Launch line → `mpirun -n $SLURM_NTASKS python run_pafi.py`
  (or `srun python run_pafi.py` if the template uses `srun`).
- Preserve `module load`, `conda activate`, `source venv/bin/activate`,
  environment variables, and any cluster-specific boilerplate **verbatim**.

If the template is minimal (bare `#SBATCH` header), ask before adding module
loads or environment activation — cluster conventions vary.

If no template is provided, do **not** fabricate one. Tell the user how to
launch with `mpirun` directly and offer to write a template if they describe
the scheduler.

## Step 5 — report the launch command

Print one of:

- `sbatch submit_pafi.sh`
- `qsub submit_pafi.pbs`
- `mpirun -n <N> python run_pafi.py`
- `python run_pafi.py` (serial)

Do **not** run the job yourself. Submitting jobs has real cost and side
effects; the user submits.

## Anti-patterns

- Guessing the calculator, potential file, or module loads.
- Rewriting the user's submission template from scratch instead of filling
  it in.
- Inlining calculator construction into `run_pafi.py` — always import.
- Writing generated files to the repo root. They go in the user's folder.
- Mocking the calculator for a "dry run". PAFI has no meaningful dry run.
- Adding CLI flags, logging frameworks, or config files the user did not
  ask for.
